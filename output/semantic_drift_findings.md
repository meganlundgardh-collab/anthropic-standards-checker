Stage B — the actual semantic comparison — needs a live model call; this sandbox has network access to `api.anthropic.com` but no `ANTHROPIC_API_KEY` configured, so the script correctly stopped rather than faking a result.

What follows is Stage B run by hand: each prompt below is copied verbatim from `semantic_drift_candidates.json`'s `stage_b_prompt` field, and each verdict is what applying that exact prompt produced. This is the honest state of this module — a real Anthropic-API integration (see `call_model()` in the script) that would run unattended with a key, executed manually this one time because no key exists in the build environment. Labeling it this way instead of quietly hand-writing "sample output" is the same principle the rest of this submission follows: say what actually ran.

## What this run actually demonstrates

**The headline result (#6) is the one the module was built to test, and it passed.** Without the DISTINCT_CONCEPT category, this checker would have flagged Claude Tag's "connection" definition as drift against the canonical connector definition — exactly the false conclusion a human would have to catch by hand, the same way the Part 2 stress test caught it in the first place. Building DISTINCT_CONCEPT in as a first-class verdict, not an afterthought, is what let the checker get this one right instead of needing a human override.

**But #7, on the same page, one section later, is real drift** — a genuine, previously-undocumented instance of Rule 1's pattern that neither Part 1's original audit nor the Part 2 stress test surfaced, because neither was looking at plugin *definitions* specifically. It's a nice demonstration that "this page correctly handles the hard case" and "this page is otherwise clean" are independent facts.

**#2 and #3 (the "hooks" drift on the Government plugins page) are the most concrete new finding this module produced.** Hooks aren't in canonical `plugins/overview.md` anywhere — confirmed by grepping the full scraped page, not just the opening summary — so a Government-surface reader would learn about a plugin capability (local hook execution) that the canonical source of truth doesn't document at all. This overlaps with, but isn't identical to, Part 1 finding #5 ("four pages, four different plugin component lists"): finding #5 was about component *tables*; this is the same drift pattern showing up in defining *prose*, which is specifically the surface Rule 1 (not Rule 2) exists to catch. Worth flagging in Part 1/Part 2 follow-up as a live example, not just a hypothetical one.

## Known limitations, disclosed rather than patched

- **Stage A's length heuristic is currently too blunt to trust on its own.** It counts every sentence in the opening block (H1 to first H2), not just sentences that are part of the definitional claim — so it flagged 8 of 8 candidate pages as "possible canonical substitute," including `/cowork/guide/plugins`, which is CONSISTENT and is Rule 1's own template-correct example. A useful version would scope the count to the sentence(s) actually forming the local definition, not the whole opening block (which often includes availability notes, admonitions, and other non-definitional prose). Left un-fixed here on purpose, same reasoning as `link_checker.py`'s stemming gap: documenting a known-bad heuristic is more useful than quietly narrowing this run's sample until it looks clean.
- **Stage A found this run's most important candidate only after a real bug fix, mid-build.** The first version of `extract_full_body()` only scanned the opening block (H1 to first H2) for definitional sentences, which missed `claude-tag/admins/add-connections.md`'s "connection" definition entirely, because it lives under that page's first H2, not before it. Widened to scan the whole page body. Left as a code comment in the script rather than silently fixed, since it's a real example of exactly the class of checker mistake this whole project has been surfacing and correcting in the open.
- **Stage B ran manually, not via the API, for this submission.** The integration code is real and would run unattended with `ANTHROPIC_API_KEY` set; see `checker/semantic_drift_checker.py`'s `call_model()`. What's in this file is that same prompt applied by a person (me) reading the same text a model would, once, without the retry/consistency-checking that a production version would need — see the README's "evaluating the checker" section for why a single judgment call (model or human) shouldn't be trusted uncritically for exactly the reason this whole project's Part 1 correction saga demonstrated.
